# Panda Print — бэкенд

Node.js + TypeScript. Две задачи:

1. **Форма обратной связи** → валидация, анти-спам, письмо на почту магазина по SMTP.
2. **Каталог с Яндекс.Маркета** → раз в 20 минут бэкенд выкачивает все товары через Партнёрский API, кладёт в кэш и отдаёт фронтенду одним эндпоинтом. Токен продавца в браузер не попадает никогда.

---

## Структура проекта

```
pandaprint/
├── frontend/                 статика: Nginx отдаёт её напрямую
│   ├── index.html  script.js  style.css  img/
├── backend/
│   ├── src/
│   │   ├── index.ts          точка входа
│   │   ├── app.ts            helmet, cors, rate-limit, роуты
│   │   ├── config/env.ts     единственное место чтения process.env
│   │   ├── routes/           маршруты
│   │   ├── controllers/      обработчики запросов
│   │   ├── services/         Маркет, кэш каталога, почта, капча
│   │   ├── schemas/          Zod: форма и ответы Маркета
│   │   ├── middleware/       лимиты, логи, ошибки
│   │   ├── jobs/             расписание обновления каталога
│   │   └── lib/logger.ts     логгер
│   ├── scripts/              вспомогательные скрипты (не идут в сборку)
│   ├── data/catalog.json     кэш на диске, создаётся сам
│   └── ecosystem.config.cjs  PM2
└── _legacy/                  старые Vercel-функции, можно удалить
```

**Почему Express, а не Fastify.** Нагрузка здесь — отдача уже готового JSON из памяти, разница в пропускной способности нерелевантна. `express-rate-limit`, `helmet` и `cors` — first-class под Express, а сам проект проще передать другому разработчику или хостеру.

**Почему встроенный `fetch`, а не axios.** Node 20+ умеет `fetch` и `AbortSignal.timeout()` из коробки. Минус одна зависимость и минус поверхность для `npm audit`.

## Быстрый старт локально

```bash
cd backend
npm install
cp .env.example .env
```

Заполните `.env` (см. таблицу ниже) и запустите:

```bash
npm run dev
```

Сервер поднимется на `http://127.0.0.1:3000`. Проверить:

```bash
curl http://127.0.0.1:3000/api/health
```

### Посмотреть сайт целиком

Фронтенд ходит по относительным путям `/api/...`, как в проде. Чтобы локально было так же, есть мини-сервер, который повторяет схему Nginx — отдаёт статику и проксирует `/api` на бэкенд:

```bash
npm run dev:site
```

Откройте `http://127.0.0.1:4173`. Бэкенд при этом должен быть запущен в соседнем окне.

## Переменные окружения

Все секреты только здесь. `.env` в `.gitignore`, в репозиторий не попадает. Сервер **не стартует**, если переменная отсутствует или заполнена некорректно, — с указанием, что именно не так.

| Переменная | Обязательна | Описание |
|---|---|---|
| `PORT` | нет (3000) | Порт Node. |
| `HOST` | нет (127.0.0.1) | Только петлевой интерфейс — наружу выставляет Nginx. |
| `NODE_ENV` | нет | `production` на сервере. |
| `LOG_LEVEL` | нет (info) | `debug` для подробностей выгрузки. |
| `CORS_ORIGINS` | **да** | Домены фронтенда через запятую. Звёздочка не поддерживается. |
| `YANDEX_API_KEY` | **да** | Токен из partner.market.yandex.ru → «Модули API». |
| `YANDEX_BUSINESS_ID` | **да** | ID кабинета (бизнеса). |
| `YANDEX_CAMPAIGN_ID` | нет | Пусто = все магазины кабинета определяются автоматически. |
| `CATALOG_REFRESH_CRON` | нет (`*/20 * * * *`) | Как часто обновлять каталог. |
| `CATALOG_REQUIRE_PUBLISHED` | нет (`true`) | Показывать только товары, опубликованные хотя бы в одном магазине. |
| `SMTP_HOST` | в проде | `smtp.yandex.ru`. |
| `SMTP_PORT` | нет (465) | 465 при `SMTP_SECURE=true`. |
| `SMTP_SECURE` | нет (true) | SSL. |
| `SMTP_USER` | в проде | Ящик на домене. Он же уходит в поле `From`. |
| `SMTP_PASS` | в проде | **Пароль приложения**, не пароль от аккаунта. |
| `MAIL_TO` | в проде | Куда падают заявки. |
| `MAIL_FROM_NAME` | нет | Отображаемое имя отправителя. |
| `SMARTCAPTCHA_SERVER_KEY` | нет | Пусто = капча выключена. |

В режиме разработки почту можно не заполнять: сервер поднимется, каталог будет работать, а `/api/contact` вернёт `503` с понятным сообщением. В `production` отсутствие SMTP — ошибка запуска, потому что молча теряемые заявки хуже, чем упавший деплой.

## Что нужно донастроить руками

1. **Токен Маркета.** partner.market.yandex.ru → «Модули API» → создать токен → в `YANDEX_API_KEY`.
2. **Пароль приложения для почты.** Отдельный ящик заводить не нужно: `razrslip@yandex.ru` может отправлять сам себе, поэтому `SMTP_USER` и `MAIL_TO` совпадают. Нужен только **пароль приложения**: id.yandex.ru → Безопасность → Пароли приложений → «Почта». Обычный пароль от аккаунта не подойдёт. Яндекс требует, чтобы `From` совпадал с авторизованным ящиком, поэтому отправителем всегда будет `SMTP_USER`. Адрес клиента подставляется в `Reply-To`, так что отвечать на заявку можно прямо из входящих кнопкой «Ответить».

   Когда появится почта на домене, достаточно поменять `SMTP_USER`/`SMTP_PASS` на ящик вида `noreply@пандапринт.shop` — остальное менять не придётся.
3. **Домен в `CORS_ORIGINS`.** Оба варианта — с `www` и без. Кириллический домен пишется как есть: приложение приводит его к punycode само, потому что браузер присылает `Origin` именно в нём (`пандапринт.shop` → `xn--80aalrwdiejw.shop`).

## API

Три эндпоинта, все под `/api`.

### `GET /api/products`

Весь каталог одним ответом, из кэша. В Яндекс на этот запрос никто не ходит.

```json
{
  "updatedAt": "2026-08-29T19:31:03.853Z",
  "count": 301,
  "products": [
    {
      "source": "Yandex Market",
      "offerId": "10101",
      "name": "Пластик Bambu Lab PLA Basic Черный, 1кг",
      "price": 2299,
      "oldPrice": 3699,
      "image": "https://avatars.mds.yandex.net/...",
      "url": "https://market.yandex.ru/card/slug/103252346944?businessId=...",
      "category": "Материалы расходные для 3D-принтера",
      "stock": 15
    }
  ]
}
```

Пагинации на выдаче нет сознательно: фронтенд сам режет список по 12 штук и считает по нему счётчики категорий. Ответ отдаётся с `ETag` и `Cache-Control: max-age=300`, поэтому повторные заходы получают `304` вместо повторной передачи всего каталога.

Лимит: 60 запросов в минуту с адреса.

### `POST /api/contact`

```json
{ "name": "Анна", "contact": "anna@example.com", "message": "Вопрос", "website": "", "consent": true }
```

`website` — honeypot, должен быть пустым. `consent` — согласие на обработку персональных данных (152-ФЗ), принимается только литеральное `true`: проверка стоит на сервере, а не только атрибутом `required` у чекбокса, иначе запрос напрямую в API обошёл бы её. Факт согласия фиксируется строкой в теле письма. Текст политики — `frontend/privacy.html`.

Ответы: `200` отправлено, `204` заявка отсеяна honeypot (для бота выглядит успехом), `400` ошибки валидации в поле `fields`, `429` лимит, `503` SMTP не настроен, `502` SMTP отказал.

Лимит: 5 запросов за 15 минут с адреса.

### `GET /api/health`

Состояние кэша: сколько товаров, когда обновлялись, была ли ошибка последнего обновления. `200` если каталог есть, `503` если ещё не загрузился.

## Как работает каталог

Партнёрский API, база `https://api.partner.market.yandex.ru`, авторизация заголовком `Api-Key`.

| Шаг | Метод |
|---|---|
| Найти магазины кабинета | `GET /v2/campaigns?limit=100` |
| Товары | `POST /v2/businesses/{businessId}/offer-mappings?limit=100&pageToken=…` |
| Остатки | `POST /v2/campaigns/{campaignId}/offers/stocks?limit=100&pageToken=…` |

**Пагинация.** `limit` максимум 100, следующая страница — по `pageToken` из `result.paging.nextPageToken`. Страницы тянутся строго последовательно: Маркет разрешает не больше 4 одновременных запросов на кабинет и отвечает `420 Enhance Your Calm` при превышении. Есть ретраи с растущей паузой и жёсткий потолок в 50 страниц как предохранитель от зацикливания.

**Остатки собираются по всем магазинам.** В кабинете Panda Print их три — `Panda_Print_Spass` (FBS), `Panda_Print_MSK` (FBS), `Panda_Print_FBY` (FBY), — и остатки у каждого свои. Товар считается доступным, если он есть хотя бы на одном складе. Полное обновление — около 16 запросов, примерно 15 секунд.

**Что отсеивается.** На момент настройки: 431 товар в кабинете → 301 в каталоге. Убираются товары без цены, с нулевым остатком (118 штук) и не опубликованные ни в одном магазине (12 штук). Товар, по которому остаток выяснить не удалось, **остаётся** в выдаче: неизвестный остаток — это не ноль, иначе одна неудачная ручка обнулила бы весь каталог.

**Кэш.** Живёт в памяти и дублируется в `data/catalog.json`. При старте снимок поднимается с диска, поэтому после рестарта или деплоя сайт отдаёт каталог с первой секунды и не идёт в Маркет на каждый запуск. Если обновление упало — в логе ошибка, а пользователям продолжает отдаваться прошлый снимок.

## Безопасность

| Что | Как сделано |
|---|---|
| Секреты | Только в `.env`, читаются в одном месте (`config/env.ts`) через Zod-схему. В коде нет ни одного захардкоженного значения. |
| Токен Маркета | Используется единственным модулем `services/yandexMarket.service.ts`, уходит только в заголовок `Api-Key`. В ответы API, в URL и в логи не попадает. |
| Rate limiting | Форма 5/15 мин, каталог 60/мин, глобально 300/мин. |
| CORS | Явный список доменов из `.env`. Запрос с неизвестного `Origin` получает `403`. |
| Helmet | Включён с дефолтами, `X-Powered-By` снят. |
| Валидация | Zod: длины полей, формат e-mail/телефона, вырезание управляющих символов. Тело запроса ограничено 32 КБ. |
| Header injection | Заголовки письма не собираются из пользовательского ввода вообще: `From` и `Subject` — константы из конфигурации, имя отправителя идёт только в тело письма, `Reply-To` ставится лишь если контакт распознан как e-mail. Тело — `text/plain`. |
| Анти-спам | Honeypot-поле `website` + лимит частоты. SmartCaptcha подключается опционально. |
| HTTPS | Node слушает `127.0.0.1` и в интернет напрямую не смотрит. TLS терминирует Nginx (см. ниже). |
| Логи | Пишутся метод, путь, код и длительность. Тела запросов не логируются никогда: по форме в лог уходит только факт отправки и признак «контакт был e-mail». Значения секретов дополнительно вырезаются из любой строки лога. |
| Зависимости | 8 прод-пакетов, `npm audit` чистый. |

Проверить всё разом:

```bash
npm run smoke
```

Скрипт гоняет санитизацию, формирование письма (включая попытку внедрить `Bcc`), каталог, CORS, валидацию формы, honeypot и лимит частоты. Последний тест расходует квоту формы на 15 минут — это ожидаемо.

## Какой хостинг подходит

Приложению нужен **постоянно работающий процесс Node.js**, а не просто место под файлы. Из этого следует всё остальное:

| Нужно | Почему |
|---|---|
| Долгоживущий процесс | `node-cron` обновляет каталог раз в 20 минут. Если процесс поднимается только на время HTTP-запроса, расписание не отработает. |
| Память между запросами | Каталог на 301 товар лежит в оперативной памяти и отдаётся мгновенно. Без этого каждый запрос ходил бы в Яндекс — медленно и упрётся в лимиты API. |
| SSH и root | Установить Node, Nginx, PM2, certbot. |
| Свои правила Nginx | Проксирование `/api/` на порт 3000 с заголовком `X-Forwarded-For` — без него rate limiting работает неверно. |

**Значит, нужен VPS/VDS, а не виртуальный (shared) хостинг.** На виртуальном хостинге обычно нельзя держать свой процесс и настраивать веб-сервер — это его принципиальное ограничение, а не вопрос тарифа.

Требования скромные: **1–2 vCPU, 2 ГБ RAM, 20 ГБ диска, Ubuntu 22.04 или 24.04**. Нагрузка — отдача готового JSON. 2 ГБ берутся с запасом на сборку TypeScript прямо на сервере; при 1 ГБ надёжнее собирать локально и заливать готовый `dist/`.

### Что брать в РУ-ЦЕНТРе

**«Хостинг и серверы» → VDS/VPS → VDS Linux.** Из четырёх продуктов в каталоге подходит только он.

| Продукт | Вердикт |
|---|---|
| Виртуальный хостинг | Не подойдёт: нет своего процесса и своего конфига веб-сервера |
| CMS-хостинг | Не подойдёт: заточен под PHP-движки, у нас Node |
| **Виртуальный сервер VDS** | **Берём. Тариф — любой от 2 ГБ RAM, образ Ubuntu** |
| Аренда выделенного сервера | Избыточно на порядок |

Отдельно **не нужны** и только увеличат счёт:

- **SSL-сертификат** и услуга «Настройка SSL» — Let's Encrypt бесплатный, выпускается certbot одной командой (ниже).
- **Услуга «Настройка домена»** — это две A-записи, шаг 0 ниже.
- **Тарифы с ispmanager** — панель сама управляет конфигами Nginx и будет конфликтовать с ручным конфигом из этой инструкции. Если всё же возьмёте её, конфиг `/api/` придётся заводить через панель, а не файлом.
- **Антивирус и «Страхование сайта»** — рассчитаны на PHP-CMS, у нас статика и Node.
- **Хостинг ФЗ-152** — бэкенд не хранит персональные данные вообще: заявка из формы уходит в письмо и нигде не сохраняется — ни в базе (её нет), ни в файлах, ни в логах. Обычный VDS в московском дата-центре. Если нужна формальная аттестация под 152-ФЗ — это вопрос к юристу, а не к архитектуре.

### Регистратор и хостинг могут быть разными

Домен в РУ-ЦЕНТРе не обязывает брать сервер там же — это независимые услуги. Схема «домен в РУ-ЦЕНТРе, сервер в Timeweb (или где угодно)» абсолютно рабочая и распространённая. Связывает их только DNS: в панели регистратора A-записи указывают на IP сервера (шаг 0 ниже).

В конфигурации приложения при этом **не меняется ничего**: `CORS_ORIGINS`, `server_name` в Nginx и certbot работают по доменному имени, а не по IP или провайдеру.

Единственное правило то же самое: нужен **облачный сервер / VPS**, а не тариф «Виртуальный хостинг». У Timeweb это две разные услуги, как и у РУ-ЦЕНТРа.

### ⚠️ Исходящие SMTP-порты часто закрыты

Многие провайдеры по умолчанию блокируют исходящие порты **25, 465, 587, 2525** на новых серверах — чтобы через взломанную машину не рассылали спам. Timeweb Cloud делает это явно и документированно.

Форма обратной связи ходит на `smtp.yandex.ru:465`, поэтому при закрытом порте письма просто не будут уходить — без внятной ошибки на сайте, только таймаут в логе.

Проверить сразу после создания сервера:

```bash
nc -zv smtp.yandex.ru 465
```

Либо, что нагляднее, прямо нашим скриптом — он проверит и порт, и пароль, и доставку:

```bash
npm run mail:test
```

Если порт закрыт, он открывается в панели управления сервером, а если такой опции нет — заявкой в поддержку. Просят обычно объяснить, зачем: ответ «отправка писем с формы обратной связи собственного сайта через SMTP Яндекса» их устраивает.

Политика отличается от провайдера к провайдеру:

| Провайдер | 465 | Что делать |
|---|---|---|
| Timeweb Cloud | закрыт по умолчанию | Открыть в панели или через поддержку |
| Рег.ру | открыт (закрыт только 25) | Ничего, работает сразу |

**Запасной вариант — порт 587.** Если 465 недоступен, Яндекс принимает почту и на 587 через STARTTLS. В `.env` меняются две строки:

```
SMTP_PORT=587
SMTP_SECURE=false
```

Транспорт в этом случае включает `requireTLS`, то есть откажется отправлять письмо, если шифрование поднять не удалось, — пароль от ящика открытым текстом не уйдёт ни при каком раскладе.

Источники: [ограничения облачных серверов Timeweb](https://timeweb.cloud/docs/cloud-servers/limitations), [закрытые порты на дашборде Timeweb](https://timeweb.cloud/blog/zakrytye-porty-na-dashborde), [настройка почты на VPS Рег.ру](https://help.reg.ru/support/hosting/nastroyka-pochty-regru/nastroyka-pochty-i-pochtovykh-kliyentovv/nastroyka-pochty-na-servere-vpss).

## Деплой на Timeweb по шагам

Конкретная последовательность для схемы «сервер в Timeweb Cloud, домен в РУ-ЦЕНТРе». Общие подробности по каждому шагу — в следующем разделе.

Команды помечены: **[Windows]** — в PowerShell на вашем компьютере, **[сервер]** — по SSH на сервере. `<IP>` везде — публичный IP сервера из панели Timeweb.

### Шаг 0. Убедиться, что куплен именно облачный сервер

В панели Timeweb должны быть: **IP-адрес**, **root-пароль** (или SSH-ключ) и выбранный образ **Ubuntu 22.04 / 24.04**. Раздел называется «Облачные серверы».

Если вместо этого в панели «Сайты», «PHP», «FTP», «Панель управления» — это виртуальный хостинг, и на нём приложение не запустится (нужен постоянный Node-процесс, см. «Если на хостинге нет root и PM2»). В этом случае дальше идти бессмысленно — сначала поменять тариф.

### Шаг 1. Подключиться по SSH

**[Windows]** — `ssh` встроен в Windows 10/11, ничего ставить не нужно:

```powershell
ssh root@<IP>
```

При первом подключении спросит «Are you sure you want to continue connecting?» — `yes`. Пароль при вводе не отображается, это нормально.

### Шаг 2. Подготовить сервер одним скриптом

**[Windows]** — залить скрипт:

```powershell
scp D:\pandaprint\pandaprint\backend\scripts\server-setup.sh root@<IP>:/root/
```

**[сервер]** — запустить:

```bash
bash /root/server-setup.sh
```

Скрипт ставит Node.js 22, Nginx, PM2, certbot, включает firewall (SSH при этом разрешается заранее, доступ не отвалится), создаёт `/var/www/pandaprint` и пишет конфиг Nginx для HTTP. Занимает 2–4 минуты. Повторный запуск безопасен.

Если увидите `$'\r': command not found` — файл сохранился с Windows-переносами строк. Лечится одной командой и повторным запуском:

```bash
sed -i 's/\r$//' /root/server-setup.sh
```

### Шаг 3. Залить код и `.env`

Git-репозитория пока нет, поэтому переносим архивом. `tar` и `scp` встроены в Windows.

**[Windows]**:

```powershell
cd D:\pandaprint\pandaprint
tar -czf pandaprint.tgz --exclude=node_modules --exclude=dist --exclude=data --exclude=logs --exclude=.env backend frontend
scp pandaprint.tgz backend\.env root@<IP>:/root/
del pandaprint.tgz
```

Архив около 6,5 МБ — без `node_modules` и сборки, они соберутся на сервере. `.env` в архив не входит намеренно и едет отдельным файлом: так его точно не забудешь и он не попадёт в копии архива.

**[сервер]**:

```bash
tar -xzf /root/pandaprint.tgz -C /var/www/pandaprint
mv /root/.env /var/www/pandaprint/backend/.env
chmod 600 /var/www/pandaprint/backend/.env
rm /root/pandaprint.tgz
```

`chmod 600` — файл с паролями читает только root.

### Шаг 4. Собрать и запустить

**[сервер]**:

```bash
cd /var/www/pandaprint/backend
sed -i 's/^NODE_ENV=.*/NODE_ENV=production/' .env
npm ci
npm run build
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup
```

`pm2 startup` напечатает команду вида `sudo env PATH=... pm2 startup systemd -u root --hp /root` — её нужно скопировать и выполнить, тогда приложение переживёт перезагрузку сервера.

Проверка:

```bash
curl -s http://127.0.0.1:3000/api/health
```

Должно вернуть JSON с `"ok":true` и количеством товаров. Первое обновление каталога занимает 10–40 секунд — если `ok:false`, подождите и повторите. Логи: `pm2 logs pandaprint-api`.

### Шаг 5. Открыть SMTP-порт

Timeweb Cloud **по умолчанию закрывает исходящие 25, 465, 587 и 2525**. Форма шлёт через `smtp.yandex.ru:465`, так что без этого шага письма молча не уйдут.

**[сервер]** — проверить:

```bash
nc -zv smtp.yandex.ru 465
```

`succeeded` — порт открыт. `timed out` / `Connection refused` — закрыт: в панели Timeweb у сервера найти настройку исходящих портов или написать в поддержку: «Прошу открыть исходящий порт 465 для отправки писем с формы обратной связи собственного сайта через SMTP Яндекса». После открытия — сквозная проверка, отправит одно тестовое письмо на `MAIL_TO`:

```bash
npm run mail:test
```

### Шаг 6. Переключить домен на сервер

Порядок важен: сервер уже работает (шаг 4), поэтому переключение DNS не оставит домен «в пустоте».

1. **В панели Timeweb** — раздел доменов → добавить `пандапринт.shop` → привязать к серверу. Панель создаст A-записи на IP сервера и покажет **свои NS-серверы** (вида `ns1.timeweb.ru`, `ns2.timeweb.ru`, …). Скопировать их точно оттуда — не с чужих инструкций.
2. **В РУ-ЦЕНТРе** — Домены → пандапринт.shop → Управление DNS-серверами → **сначала** DNSSEC → Настроить → убедиться, что выключен (если включён — выключить и подождать сутки, иначе домен исчезнет из DNS целиком).
3. **Там же** — выбрать «Указать DNS-серверы самостоятельно», вписать NS Timeweb, сохранить.
4. Ждать. Обычно 15 минут – 2 часа, формально до 24 часов. Проверять **[Windows]**:

```powershell
nslookup xn--80aalrwdiejw.shop 8.8.8.8
```

Как только команда показывает `<IP>` вашего сервера — DNS доехал, и `http://пандапринт.shop` уже должен открывать сайт (пока по HTTP).

### Шаг 7. Сертификат

Только после шага 6 — Let's Encrypt проверяет владение доменом, обращаясь к нему по HTTP.

**[сервер]**:

```bash
certbot --nginx -d xn--80aalrwdiejw.shop -d www.xn--80aalrwdiejw.shop
```

Спросит e-mail для уведомлений о продлении и согласие с условиями. На вопрос про редирект HTTP→HTTPS — **2 (Redirect)**. Certbot сам допишет HTTPS-блок в конфиг Nginx и настроит автопродление — проверить его можно так: `certbot renew --dry-run`.

### Шаг 8. Финальная проверка

- `https://пандапринт.shop` — открывается с замком, каталог грузится
- Форма: отправить тестовую заявку с галочкой согласия — письмо пришло на `MAIL_TO`
- Превью ссылки в Telegram: кинуть ссылку на сайт себе в «Избранное» — должна появиться карточка с картинкой (OG-теги)
- `pm2 status` — процесс `online`, `pm2 logs pandaprint-api --lines 50` — без ошибок

### Обновление в будущем

> **Если меняли `style.css` или `script.js` — поднимите версию в ссылках.** Nginx отдаёт их с кэшем на 30 дней, и без этого посетители (и вы сами на телефоне) будут видеть старую версию. ## Деплой на VPS (PM2 + Nginx) — справочник

### 0. Направить домен на сервер

Домен сейчас в режиме «Статусная страница»: делегирован на `ns3/ns4/ns8.nic.ru`, A-запись ведёт на заглушку РУ-ЦЕНТРа (`178.210.92.188`, отдаёт 404). Режим надо сменить: **Домены → пандапринт.shop → Управление DNS-серверами**.

**Сервер у стороннего провайдера (Timeweb и т.п.)** — выбрать «Указать DNS-серверы самостоятельно» и вписать NS провайдера. Точные имена берутся в панели провайдера при добавлении домена, наугад их писать нельзя. После этого зона ведётся там же, где сервер, и A-записи провайдер проставит сам.

Вариант «вести зону в РУ-ЦЕНТРе и просто поменять A-записи» тоже рабочий, но требует их услуги DNS-хостинг (DNS-master), которая заказывается отдельно и платно. У облачных провайдеров DNS обычно входит в стоимость сервера, поэтому смысла платить дважды нет.

**Сервер в самом РУ-ЦЕНТРе** — оставить режим «Хостинг», домен подхватит их же хостинг автоматически.

> **DNSSEC — выключить до смены NS.** Если он включён, при переезде на другие серверы имён подписи перестанут сходиться, и домен исчезнет из DNS целиком: не «сайт не открывается», а «домена не существует». Сначала выключаем DNSSEC, ждём сутки, потом меняем NS. Включить обратно можно уже на новых серверах.

Смена NS расходится по DNS до 24 часов (обычно быстрее). Проверять так:

```bash
nslookup xn--80aalrwdiejw.shop 8.8.8.8
```

Пока команда не показывает IP вашего сервера, certbot сертификат не выпустит — проверка Let's Encrypt ходит по домену. Поэтому порядок именно такой: сначала сервер, потом NS, потом сертификат.

### 1. Код и сборка

```bash
git clone <репозиторий> /var/www/pandaprint
cd /var/www/pandaprint/backend
npm ci
npm run build
cp .env.example .env && nano .env
```

### 2. PM2

```bash
npm install -g pm2
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup
```

Конфигурация намеренно запускает **один** процесс в режиме `fork`. Кэш каталога и счётчики лимитов живут в памяти, поэтому кластер из N воркеров дал бы N независимых кэшей и лимит формы, умноженный на N.

Полезное: `pm2 logs pandaprint-api`, `pm2 restart pandaprint-api`, `pm2 monit`.

### 3. Nginx

Домен кириллический, поэтому в конфиге Nginx и в certbot он указывается **только в punycode** — Unicode там не поддерживается:
`пандапринт.shop` → `xn--80aalrwdiejw.shop`.

```nginx
server {
    listen 80;
    server_name xn--80aalrwdiejw.shop www.xn--80aalrwdiejw.shop;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name xn--80aalrwdiejw.shop www.xn--80aalrwdiejw.shop;

    ssl_certificate     /etc/letsencrypt/live/xn--80aalrwdiejw.shop/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/xn--80aalrwdiejw.shop/privkey.pem;

    # Статика отдаётся напрямую, Node к ней не подключается.
    root /var/www/pandaprint/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~* \.(css|js|png|jpg|jpeg|svg|webp|woff2)$ {
        expires 30d;
        add_header Cache-Control "public";
    }

    # API проксируется на Node.
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # Без этих двух заголовков rate limiting увидит всех клиентов
        # как 127.0.0.1, и один спамер заблокирует форму для всех.
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Host $host;
        proxy_read_timeout 30s;
    }
}
```

В приложении стоит `app.set('trust proxy', 1)` — ровно один прокси. Если перед Nginx появится ещё один слой (например CDN), это число нужно увеличить, иначе адрес клиента определится неверно.

### 4. Сертификат и firewall

```bash
certbot --nginx -d xn--80aalrwdiejw.shop -d www.xn--80aalrwdiejw.shop
ufw allow 22,80,443/tcp && ufw enable
```

Порт 3000 наружу открывать не нужно и нельзя: Node слушает только `127.0.0.1`.

### 5. Обновление

```bash
cd /var/www/pandaprint && git pull
cd backend && npm ci && npm run build && pm2 restart pandaprint-api
```

Каталог при рестарте поднимется с диска мгновенно и обновится в фоне.

### Если на хостинге нет root и PM2

На виртуальном хостинге (в отличие от VPS) долгоживущий процесс может быть недоступен, а PM2 не установить. Тогда приложение запускается через панель управления Node.js-приложениями хостинга: точка входа `backend/dist/index.js`, переменные окружения задаются в панели. Код к этому готов: кэш дублируется на диск, а `/api/products` никогда не ходит в Маркет синхронно, поэтому перезапуски процесса каталог не ломают. Единственное, что теряется, — гарантия срабатывания `node-cron`, если процесс усыпляют между запросами; проверить это можно по полю `updatedAt` в `/api/health`.

## SmartCaptcha (опционально)

Сейчас форму защищают honeypot и лимит частоты. Если спам всё-таки пойдёт, капча включается без изменений в коде бэкенда:

1. В Yandex Cloud создайте капчу, получите **клиентский** и **серверный** ключи.
2. В `.env` бэкенда: `SMARTCAPTCHA_SERVER_KEY=<серверный ключ>`.
3. В `frontend/index.html` — подключить скрипт и вставить контейнер внутрь формы:

```html
<script src="https://smartcaptcha.yandexcloud.net/captcha.js" defer></script>
<div class="smart-captcha" data-sitekey="<клиентский ключ>"></div>
```

4. В `frontend/script.js`, в теле запроса к `/api/contact`, добавить поле:

```js
captchaToken: valueOf('smart-token'),
```

Бэкенд начнёт проверять токен автоматически, как только серверный ключ окажется непустым. Если сервис проверки недоступен, заявка пропускается (терять обращения клиентов из-за чужой аварии хуже, чем пропустить спам) — лимит частоты при этом продолжает действовать.

## Диагностика

**Каталог пустой, `/api/health` отдаёт 503.** Первое обновление ещё не прошло либо упало. Смотрите `lastError` в ответе `/api/health` и лог `pm2 logs`.

**В логе `Маркет ответил 401`.** Токен неверный или отозван. Перевыпустите в «Модулях API».

**В логе `Маркет ответил 420`.** Упёрлись в лимит одновременных запросов. Обрабатывается ретраями автоматически; если повторяется постоянно — значит, кто-то ещё ходит в API тем же токеном.

**`Формат ответа Маркета изменился`.** Яндекс поменял схему ответа. Запустите `npm run probe`, сверьте с `src/schemas/market.schema.ts`.

**Форма отвечает 503.** Не заполнены `SMTP_*`. При старте сервер пишет об этом предупреждение и проверяет соединение с SMTP.

**Письма не доходят.** Убедитесь, что в `SMTP_PASS` пароль приложения, а не пароль от аккаунта, и что `SMTP_USER` — реально существующий ящик на вашем домене.
